## ERR-DY-001 | 拿「设定画集」当图生图参考，模型连版式一起抄进四格

- 症状: 用人类给的完整人设图做参考，生成的四格里直接出现「数字生命伙伴」「表情差分」这些文字和一圈小图，完全不能用。
- 错误原文: `无报错，只有产物不可用（画面里带出画集的文字与三视图版式）`
- 触发条件: 直接用含三视图/表情/文字说明的完整人设图喂图生图。
- 根因: 参考图里的版式与文字被模型当成画面内容。
- 解决: 先用画集重生一张**纯白底单人立绘**（`assets\character\lanyin-clean.png`），再用它当长期参考——干净参考换干净出图。
- 证据: `MEMORY-<name>.md` 第 2153–2157 行
- 回滚点: 原画集与 `形象-干净版.png` 都在
- 防护: 形象图处理时，浅色主体 + 白色贴纸边**无法用简单的阈值+腐蚀分离**——第一版自动抠图把脸部、围裙这些浅色区当背景挖掉，第二版改成手工框选只裁不抠才完整。同类图先手工裁，别指望自动抠

## ERR-DY-002 | 字符级断行永远切坏中文词：<name>的第一个视频 → <name>的第 + 一个视频

- 症状: 卡片/封面标题被切在词的中间，还出现行首虚词。
- 错误原文: `实际切坏的样本：「<name>的第一个视频」→「<name>的第」+「一个视频」；「能出图的流水线」→「流」+「水线」；「我给自己做了个视频」→「了个视频」`
- 触发条件: 按字符数断行的排版逻辑。
- 根因: 字符级断行处理不了中文分词。加过「行首禁忌」「行尾禁忌」「序数词禁忌」三轮规则，每次只解决单个例子（第四次踩）。
- 解决: **单行优先**——先在所有候选字号里找能整句一行的最大字号，找不到才折行；封面和卡片两处都改成两轮循环。
- 证据: `MEMORY-<name>.md` 第 2159–2164 行
- 回滚点: 无
- 防护: 以后凡是标题/文案排版，先想这一条

## ERR-DY-003 | 条件创建的画刷被无条件 Dispose：不能对值为 Null 的表达式调用方法

- 症状: 改成条件分支后整个卡片渲染失败，报的是看起来毫不相干的错误。
- 错误原文: `不能对值为 Null 的表达式调用方法`
- 触发条件: `render-comic.ps1` 里 `$bgBrush` 只在「无插图」分支创建，但尾部仍无条件 `$bgBrush.Dispose()`。
- 根因: 给变量加了条件赋值，没同步把 Dispose 改成判空。
- 解决: 尾部 Dispose 改成判空。
- 证据: `MEMORY-<name>.md` 第 2166–2169 行
- 回滚点: 无
- 防护: 给变量加条件赋值时，顺手把它的 Dispose 也改成判空

## ERR-DY-801 | 抖音评论采集链路失效：签名器路径写死 + SDK 缺失 + 输出协议不兼容

- 症状: 连续多轮（10-22 起至 10-25）报告零评论证据；round-evidence.json 中 5 条带 top_comments 键，值全部为空数组 []，即结构在、内容为空；「好不好玩」最有力证据长期缺失。
- 错误原文: `NotADirectoryError WinError 267「目录名称无效」`（api-comments.py:20 把 PLUGIN 硬编码为 D:/aiagent/deepseek/dsh-douyin-scroll，sign() 里 subprocess.run(cwd=PLUGIN) 抛错）
- 触发条件: 一轮抖音运营需要读某条视频的评论时（douyin_comments / top-comments 链路）。
- 根因: 两层叠加：① 路径写死到本机不存在的目录，签名器从未被执行；② 改对路径后仍不可用——dy-signer.mjs 依赖的 signer/sdk/ 下 7 个 SDK 文件（webmssdk.js / secsdk-runtime.js / sdk-glue.js / bdms-signer.js / slardar.js / captcha-sdk.js / verifycenter.js）全部缺失，bdms.init 失败；另 index.js:2668 以正则解析其多行文本输出（形如「  cid=… 用户 [正文] 赞N 时间」），而替代方案 comment-read-dom.mjs 输出单个 JSON 对象，协议不兼容，直接替换会得到同样的空数组。
- 解决: 待修（A′ 方案已定）：在持久目录 ~/.dsh/douyin-duty/top-comments.mjs 建适配层，调 comment-read-dom.mjs 并把 JSON 转成现有行格式；index.js:2667 改一行指向适配层；升级后只需重改该行，逻辑不随升级丢失；另写 PATCH.md 说明重打步骤。
- 证据: `logs/failures/2026-10.jsonl` F-2026-10-0034（L35）。
- 防护: 插件是别人的包，不要在包内改逻辑；走持久目录适配层（PATCH.md 记录重打步骤）。

## ERR-DY-907 | 抖音 web 接口 403：缺 a_bogus / X-Bogus 签名（签名够了写接口仍可能 403）

- 症状: 直接对 `https://www.douyin.com/aweme/v1/web/comment/list/` 一类 web 端点发请求，返回 403、body 为空、没有任何 message；参数里补上正确 `a_bogus` 之后，同一端点 339 ms 返回干净 JSON。读评论走通之后，发评论仍 403、body 空。
- 错误原文: `HTTP 403`（响应 body 为空，无 message / 无 retcode）
- 触发条件: 不带 `a_bogus`（旧端点是 `X-Bogus`）以及配套 web 端上下文（visitor id / msToken 等）直接打 `/aweme/v1/web/*`；或从读接口迁到写接口（`comment/publish`）时。
- 根因: 抖音 web 端要求前端生成的签名参数，签名由 bdms.js 一类混淆脚本产出，依赖请求参数、UA、时间与环境指纹；缺签名即被当爬虫拒绝。**上游没有官方文档** —— 这条链路上游只有社区逆向实现，引用时别写成"官方签名算法"。另有部分端点（写接口）额外要求 `x-secsdk-web-signature`（由 visitor id 派生的浏览器签名），此时 a_bogus 不足以通过（该结论来自 Evil0ctal/Douyin_TikTok_Download_API 的 `src/dtk/signing/protection.py` 注释，属项目内解释，未独立验证）。
- 解决: 本机做法：读评论抄开源实现 —— Evil0ctal/Douyin_TikTok_Download_API（Apache-2.0）的端点表 + 参数表，配它的纯 Python `tools/abogus.py`（34.4 KB，从 bdms.js 逆向）与 `tools/sm3.py`，只改一处 import 就能用，实测 339 ms；**发送**仍走浏览器 DOM 自动化（慢但能发），不要指望签名包打天下。上游 / 社区资源：多份 a_bogus 实现可交叉验证（纯 Python、JS、C++ 都有），其中 hanzheng1954/douyin-abogus-analysis 记录了动态 trace + VM 反汇编 + SM3 管线的完整还原过程。这些全是**社区逆向**，随抖音前端更新会失效，必须保留自己重新提算法或升级依赖的能力。
- 证据: [Evil0ctal/Douyin_TikTok_Download_API（Apache-2.0，含 a_bogus 实现与端点表）](https://github.com/Evil0ctal/Douyin_TikTok_Download_API)；[hanzheng1954/douyin-abogus-analysis（a_bogus 逆向分析：trace / VM / SM3）](https://github.com/hanzheng1954/douyin-abogus-analysis)；[ylcangel/douyin_sign（a_bogus / x-bogus / msToken 的 JS 实现，Apache-2.0）](https://github.com/ylcangel/douyin_sign)；本机 `MEMORY-<name>.md` L6399-6429
- 回滚点: 无
- 防护: **全部为社区逆向，上游无官方文档**（本条的"防护"只能写成约定）：签名失效的第一信号是 `403 + 空 body`，不是 retcode；先确认 cookie / visitor id / msToken 是否还有效，再怀疑算法；写接口的 `x-secsdk-web-signature` 需求只在一个项目源码注释里见过，引用时标注未独立验证。
